## 1. 目標與範圍

v0.1.1 為修補版，讓使用者看得清楚失敗原因、修正輸入後能正常重試，並避免版本顯示及發布文件互相矛盾。以小範圍修正既有行為為主，不加入新 SNMP 能力或畫面美化。

本規格已納入確認的架構與任務基準，文件確認不代表產品實作已授權。獲得實作授權後再執行本版任務；可在同一份規格追蹤這次小修補，不必複製整套 v0.1.0 文件。重要架構／需求變更仍先討論。

## 2. 已觀察問題與證據界線

### 2.1 輸入錯誤可能被狀態刷新覆蓋

依 MainWindow 原始碼：IP／port 的驗證失敗會在 Start_Click 的 catch 直接寫入 Status.Text，但每秒執行的 Refresh 會再依 SimulatorSession.State／Error 重寫該區域。這類驗證尚未進入 session，因此 session 不一定保存該錯誤。

可能結果包括：錯誤文字短暫出現後變成「已停止」，或舊 session 的錯誤再次出現。這是本次原始碼檢視發現的問題，尚未以 Windows 重現紀錄定案，實作前需建立可失敗的重現／測試。

### 2.2 版本與文件狀態存在多處來源

Directory.Build.props 已集中版本，但 App.xaml／MainWindow.xaml／MainWindow.xaml.cs 仍有固定文字版本的風險；目前實際版本文字位於 MainWindow.xaml 與 MainWindow.xaml.cs。README、CHANGELOG 部分內容也仍描述 v0.1.0 候選或未發布，與使用者已發布的狀態不一致。

本版整理顯示與紀錄，不改寫 v0.1.0 tag，不把未完成的授權核對或未取得的歷史資料自行標成通過。

## 3. 修正需求

| 編號 | 需求 | 完成條件 |
| --- | --- | --- |
| FIX-01 | 錯誤訊息穩定保留 | 無效 IP、無效 port、檔案／資料驗證、綁定與啟動錯誤均能讀取；定時刷新不得清除或換成其他歷史錯誤 |
| FIX-02 | 定義清楚的錯誤更新時機 | 新一次操作的錯誤取代前一次錯誤；有效的新一次啟動進入 Starting 時清除舊錯誤，成功後顯示正確 Running 狀態；單純經過時間不清除錯誤 |
| FIX-03 | 修正後可重試 | 停止／失敗狀態下可更正 IP、port 或檔案再啟動；失敗不得留下 listener、停用操作或要求重開程式；成功後停止／重啟仍正常 |
| FIX-04 | 正常取消與關閉維持正確 | 使用者停止或取消不顯示為啟動錯誤；關閉不得因狀態回報卡住。若僅是無效輸入，不能動到仍在執行的合法工作階段 |
| VER-01 | 版本由集中來源取得 | 組件／檔案版本以 Directory.Build.props 為準；視窗顯示由組件版本取得，顯示 v0.1.1，避免另維護固定版本字串 |
| DOC-01 | 使用與發布紀錄符合事實 | 更新 README、CHANGELOG 與本版驗證結果；v0.1.0 已發布與 v0.1.1 未發布分開，保留歷史驗收及尚未完成項目 |

錯誤內容至少說明「哪個輸入或階段失敗」及可採取的修正方向，不要求額外對話框、通知系統、事件面板或版面重設。內部詳細例外不得直接當成唯一的使用者說明。

錯誤可與執行狀態分開保存；狀態刷新從同一份有效顯示狀態讀取。具體類別與綁定方式可在實作時依現有結構選擇，避免為此小修補引入大型 UI 框架。

## 4. 相容性與非目標

- 延續 .NET 10、Windows 10 22H2／Windows 11 x64、WPF、單設備與可攜單檔發布。
- 延續 SNMP v1／v2c GET、GETNEXT、v2c GETBULK 與唯讀限制；不改動封包語意、community、預設端點、計數方式或資源上限。
- schemaVersion 維持 1；v0.1.0 的內建七個 OID 與有效 JSON 仍可使用。
- 不新增套件為原則；若確需新增，依現有 MIT／寬鬆相依政策處理。
- 不包含 OID 表格／編輯器、網卡選單、最近檔案、設定記憶、分類統計、完整介面範例；這些見 [v0.2.0 規劃](../roadmap.md)。
- 不包含 walk 匯入、多設備、v3、SET 寫入、圖表、主題切換、效能最佳化或 p99／500 ms 驗收。

## 5. 驗收案例

案例結果以 [本版驗證紀錄](v0.1.1-verification.md) 為準，Windows 人工項目仍待執行。下列「至少三次刷新／三秒」只用於驗證訊息不被既有計時器覆蓋，不是新增反應時間或效能承諾。

| 案例 | 操作 | 預期 |
| --- | --- | --- |
| AC11-01 | 輸入無效 IPv4 後開始，等至少三秒 | IP 錯誤持續可見，沒有 listener，不被「已停止」覆蓋 |
| AC11-02 | 分別輸入非數字、0、65536 的 port 後開始 | 顯示對應錯誤且持續可見；沒有非法監聽 |
| AC11-03 | 先造成檔案／綁定錯誤，再以無效 IP 重試 | 顯示最新的 IP 錯誤，刷新不會還原舊錯誤 |
| AC11-04 | 新增不存在路徑、壞 JSON、重複 OID 的測試，再修正檔案 | 錯誤可讀且不啟動；修正後同一視窗可成功模擬 |
| AC11-05 | 端點被占用而失敗，釋放後再啟動 | 可恢復並回應查詢，無殘留 socket；新階段清除舊錯誤 |
| AC11-06 | 成功啟動、停止、再次啟動，再取消／關閉 | 正常狀態及計數維持既有規則，取消不顯示成錯誤，程序正常結束 |
| AC11-07 | 執行既有核心／UDP 與獨立用戶端互通檢查 | 既有成功行為不退化，測試失敗有非零結束碼；記錄當次實際案例數 |
| AC11-08 | 使用 v0.1.0 JSON，在另一台主機做代表性 v1／v2c 查詢 | 仍可查詢既有七個 OID，型別與值正確；維持停止後重新開始才載入修改 |
| AC11-09 | Windows 發布產物啟動並檢查版本 | EXE 的組件／檔案版本與視窗一致為 0.1.1；tag v0.1.1 與來源版本一致 |
| AC11-10 | 下載正式 tag 建置的 Release Assets | EXE／ZIP 可取得，來源 commit 及 SHA-256 可核對，授權內容隨交付保留 |

錯誤選擇、替換及清除邏輯應有可自動測試的入口；既有每秒 UI 更新不得成為只能靠人工才測得到的隱藏規則。Windows 人工補驗涵蓋實際訊息持續顯示、修正後恢復、啟停及版號，不能用 Linux 交叉建置代替。

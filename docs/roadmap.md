# 後續版本規劃

狀態：規劃清單，不是已完成承諾或實作授權。

更新日期：2026-11-06。

原則：先提升模擬與測試實用性，再評估畫面美化。版本號只表示規劃方向，實際範圍經需求確認後決定，不預設日期。

## v0.1.1 — 修補既有行為

詳見 [v0.1.1 Spec](releases/v0.1.1-spec.md)，目前為待確認草稿。重點為錯誤訊息被刷新覆蓋、錯誤後重試及版本／文件一致性；不進行新增功能或畫面改版。

## v0.2.0 — 候選事項，只列規劃

以下尚未產生完整需求、架構變更或實作任務。P1／P2 為討論順序，不是全部必須在 v0.2.0 完成；可依工作量拆成後續版本。

| 編號 | 優先度 | 項目 | 功能目標與邊界 |
| --- | --- | --- | --- |
| R20-01 | P1 | 完整且一致的小型設備範例 | 提供雙介面設備的基本介面 table，讓監控系統能探索名稱、索引、狀態、速率與計數器；ifNumber 與實際資料一致。先固定值，不引入動態流量引擎 |
| R20-02 | P1 | 載入資料的唯讀 OID 檢視 | 顯示 OID、型別、值與搜尋，方便確認載入內容；固定值與 uptime 等動態值的顯示方式再定義。先不做編輯器或頻繁刷新全部資料 |
| R20-03 | P1 | 網路端點選擇與說明 | 選擇本機 IPv4／網卡並辨識 loopback，顯示實際監聽端點；不自動加 IP 或改防火牆，不擴張為多設備 |
| R20-04 | P1 | 設備設定檔操作 | 明確切回內建範例、匯出範例與停止後重新載入；執行中維持資料快照。重新載入失敗時的舊資料處理需另定義，不悄悄退回其他設備 |
| R20-05 | P1 | 可解釋的拒絕／錯誤統計 | 區分錯誤 community、無效封包、不支援操作、超限等原因，說清楚本機送出與端到端成功的差異；不得把應用丟棄稱為網路丟包 |
| R20-06 | P2 | 每秒收送量與有限事件紀錄 | 顯示近期活動，事件使用固定容量／抽樣或限速，預設不寫逐筆封包日誌；不視為正式效能或丟包量測 |
| R20-07 | P2 | 最近檔案與操作設定記憶 | 保存上次端點／資料來源，啟動時確認再開始；需先定義可攜模式的儲存位置、失效路徑與是否保存 community，避免無意攜帶敏感設定 |

這些畫面元素以支援實際操作為目的，先保持現有 WPF 結構。UI 主題、動畫、圖表儀表板、裝飾性版面與授權按鈕位置調整不列入必要項目。

## 更後面的候選方向

| 方向 | 進入規劃前需釐清 |
| --- | --- |
| 真實設備 SNMP walk 匯入 | 二進位 OctetString、Counter64、型別保真、匯入安全與取消、schema 相容性；功能成熟後才考慮背景自動擷取 |
| 高吞吐量與多核心 | 建立可重現負載與基準，再決定需要的最佳化；報告 p99 與失敗率，500 ms 保留暫定目標 |
| 多設備 | IP／port 識別、資料隔離、socket 與生命週期、記憶體共享及實際網路配置 |

本清單不改變 v0.1.0 的發布內容，也不提前實作未確認功能。每版開始時先選定範圍並建立可驗收 Spec，發現新缺陷則另行評估是否進入修補版。

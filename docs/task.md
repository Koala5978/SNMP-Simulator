## 3. 核心資料與協定

### T00 — 確認原型基準與可重現命令

- **對應：** RUN-01；架構第 3、11 節。
- **工作：** 檢視並保留現有未提交內容；區分原型、已確認文件、分支政策與生成產物。確認 .NET 10、三個專案、內建資料及現有建置／測試命令。
- **完成條件：** 有清楚的基準紀錄，指出哪些檔案尚未提交、目前分支及已有檢查結果；生成輸出不混入來源。後續經授權提交時，能按原型／文件／修正分開提交，工作分支從 develop 建立並經 PR 回 develop。
- **驗證：** 在儲存庫根目錄重跑既有 smoke runner 與適用建置，保留實際 exit code；若失敗先診斷，不直接刪除原型或重新生成覆寫。
- **授權補充（LIC-01～03）：** 建立初步相依清單，記錄直接／遞移套件、runtime／原生元件、開發工具與其他素材的版本、來源、授權及用途；先找出未知或不符政策項目，不把沒有額外 PackageReference 當成沒有第三方元件。此盤點目前尚未執行。

### T01 — 設定檔驗證、背景載入與限制

- **對應：** DATA-02～04、DATA-06、DATA-08、UI-05；AC-07。
- **工作：** 保留 schemaVersion=1 與來源選擇行為；把讀檔、驗證移出 UI thread。處理 null、缺少欄位、錯誤 schema、重複／不合法 OID、未知型別與數值超界，提供可定位的錯誤。定義檔案位元組上限及取消行為；新增使用者可見限制時記錄理由，若影響既定需求先確認。
- **完成條件：** 有效檔可載入，無效資料不啟動 listener；明確選取的外部檔案失敗時不靜默回退範例。載入中不阻塞 UI，並可取消；限制不只在讀完整檔案後才檢查。
- **驗證：** 有效範例；空檔、壞 JSON、null、必要欄位缺漏、錯誤型別、數值邊界、重複／非法 OID；已選定的大小上限兩側；載入取消。檔案修改與重載的端到端案例在 T06／T07 補驗。

### T02 — 設備快照、OID 索引與 uptime

- **對應：** DATA-01、DATA-04～05、DATA-07～08；AC-03～05。
- **工作：** 啟動時建立不可變、型別化的資料快照與數字 OID 索引，保留精確查找及二分搜尋；建立可辨認的純量物件資訊。固定值可預編碼，uptime 由本次單調時鐘計算。
- **完成條件：** 收包時不讀 JSON 或存取可被 UI 修改的集合；`.2` 排在 `.10` 前；外部修改原資料不改變本次快照。七個範例 OID 的型別與值正確，uptime 以百分之一秒遞增、每次開始重設並按 UInt32 溢位。
- **驗證：** 所有支援型別及邊界；不等長 OID、相同前綴、首尾與相鄰搜尋；快照隔離；可控制時間的 uptime 遞增／重設／溢位案例，不依賴長時間等待。

### T03 — GET／GETNEXT、錯誤及唯讀語意

- **對應：** SNMP-01～03、SNMP-05～07；AC-03～06。
- **工作：** 分離傳輸、BER 與請求處理責任，保留不開 socket 的測試入口。核對 v1／v2c 版本、request-id、多 varbind、錯誤索引、缺失物件／實例、walk 結束及唯讀拒絕。
- **完成條件：** v1／v2c 查詢符合已確認需求；SET 不改變資料；錯誤 community、不支援版本／操作不回應。單一壞封包不終止 listener。純量推斷不宣稱等同完整 MIB／table 支援。
- **驗證：** 七個 OID 逐筆與多筆 GET、GETNEXT 完整 walk、v1 首個出錯索引與原始 varbind、v2c 三種例外、SET 前後資料、request-id 邊界、錯誤 community。加入固定封包或獨立來源案例，不只用同一套編碼器自我驗證。
- **需先釐清時：** 若核對標準發現目前錯誤行為與需求矛盾，提出具體封包、條文與修改建議，再決定變更；不保留錯誤只為讓既有測試通過。

### T04 — GETBULK、解析及回應資源上限

- **對應：** SNMP-04、SNMP-08；AC-04、AC-06。
- **工作：** 實作有界 GETBULK、varbind 順序與結束行為；集中解析／輸出限制；統一所有回應（含 tooBig）的最終大小檢查，核對 v1／v2c 的超限語意。
- **完成條件：** non-repeaters 與 max-repetitions 正確處理；不無界展開、不先配置巨大輸出再限制。一般與錯誤回應都有最終檢查，不能因 v1 帶回原 varbind 而繞過安全界線。原型的 100 repetitions／256 varbind／1400 bytes 是設計起點，採用或調整都要記錄原因及超限行為。
- **驗證：** 零／負參數、non-repeaters 超過請求數、多 repeater、部分與全部結束、上限邊界、空 varbind、畸形／截斷／尾隨 BER、過大請求、v1／v2c tooBig 最終封包。測試確認實際大小及工作有界，不只檢查錯誤碼。

## 4. 執行、視窗與 UDP

### T05 — 工作階段、取消與清理

- **對應：** DATA-01、DATA-05、UI-02～03、UI-05；AC-05、AC-08。
- **工作：** 集中 Stopped／Starting／Running／Stopping／Faulted 狀態及資源所有權；將 UI 通知與核心生命週期分離；成功綁定後才開始計時並通知就緒。
- **完成條件：** 一次一個 listener；開始中及執行中可取消，停止完成後才允許重啟。驗證、綁定或執行失敗都釋放資源；舊回呼不覆蓋新狀態，關閉視窗不因 Dispatcher 等待造成死鎖。
- **驗證：** 綁定被占用端點、非本機位址、開始中取消、等待接收時停止、送出取消、錯誤後同端點重啟；確認 Task 完成與 socket 釋放。取消顯示為正常停止，不當成錯誤吞掉所有例外。

### T06 — WPF 操作與累計統計整合

- **對應：** UI-01～05、DATA-02、DATA-08；AC-02、AC-07、AC-09。
- **工作：** 接上背景載入與工作階段，維持選檔、內建範例、IP／port、啟停及每秒累計統計。明確設定啟動中／執行中可操作控制項，錯誤保留可讀原因。
- **完成條件：** 不重複啟動，不在 UI thread 處理逐筆封包；本次統計歸零、停止後保留最後值。修改檔案只在停止後重新開始生效，預設不記逐筆日誌；不新增未需求化的圖表或 p99 儀表。
- **驗證：** 能自動化的狀態與命令邏輯先測；Windows 實際選檔、畫面響應、錯誤提示、關閉及統計顯示交由 T11 補驗。區分「本機送出成功」與「用戶端收到」，不將核心丟包加入應用計數。

### T07 — 實際 UDP 收送與生命週期測試

- **對應：** SNMP-01～08；AC-03～08。
- **工作：** 用獨立用戶端 socket 經 IPv4 loopback 對實際 listener 發送封包，測代表性成功／拒絕／錯誤／超限與重啟；測試選可用 port，採固定 timeout 與失敗結束碼。
- **完成條件：** 驗證內容、版本、request-id、來源端點及停止後可重啟。不同來源用戶端的回應不互相混淆；該丟棄的請求在測試期限內無回應，之後正常請求仍成功。
- **驗證：** 原有 smoke 檢查繼續成立，新增的代表案例完成；啟動就緒與清理均由可觀察訊號確認，不靠盲目等待。Linux 可先執行，但 Windows 結果仍須由 T09 取得。
- **界線：** 多用戶端為功能測試，不是吞吐量或 500 ms 驗收；不依據 loopback 結果宣告內網互通。

### T09 — GitHub Windows 建置／測試 CI

- **對應：** RUN-01～02；AC-01、AC-03～08；需求第 7.1 節。
- **工作：** 建立 Windows x64 workflow，使用 .NET 10，依序還原、建置、核心／UDP 測試、發行及上傳產物與結果；應測 PR 實際候選內容並記錄 SHA。一般建置使用低權限 pull_request／push 事件，不借用高權限 pull_request_target 執行 PR 程式。
- **完成條件：** 至少一次 GitHub 實際執行成功，確認測試有執行而非零案例；失敗能使 job 失敗。能下載與該次 run／commit 對應的 EXE。既有 main-source-policy 不能代替應用測試。
- **驗證：** 保存 workflow run 連結、檢查紀錄、測試結果及產物雜湊；適用時可加入發布 EXE 啟動檢查，但程序存在不算 GUI 功能完整驗收。
- **阻礙處理：** 先使用既有 GitHub 認證；若 API／Actions 權限不足，記錄被拒絕操作與必要使用者動作，繼續可執行的本地檢查，不宣稱 CI 已通過。

### T10 — 外部 SNMP 工具互通

- **對應：** SNMP-01～07；AC-03～06。
- **工作：** 用獨立 SNMP 工具（例如 Net-SNMP）驗證，不只依賴本專案自己的測試編碼器。AI 環境可安裝與執行時先自動化，否則提供相同指令由使用者補驗。
- **完成條件：** v1／v2c GET 與 GETNEXT walk、v2c GETBULK／bulkwalk 取得正確資料；七個 OID、型別、uptime 與結束行為可辨識。錯誤 community 無回應、SET 不改值。工具版本、命令與結果留存。
- **驗證：** 保存命令、端點與去除敏感資料後的輸出；測試錯誤 community 時設定明確 timeout／重試次數。此任務可在 loopback 做，不取代 T12。

### T11 — Windows GUI、最低 OS 與無 runtime 驗收

- **對應：** RUN-01～03、UI-01～05、DATA-02、DATA-08；AC-01～02、AC-05、AC-07。
- **工作：** AI 提供逐步清單，由使用者在 Windows 10 22H2 x64 及 Windows 11 x64 驗收。至少一個對應支援 OS 的乾淨實機／VM 無預裝 .NET，驗證攜帶 EXE 即可執行；記錄每個環境實際涵蓋項目，不推論未測組合已通過。
- **完成條件：** 內建範例與外部 JSON 能啟動；選檔、錯誤提示、開始／停止／重啟、關閉、統計與重新載入符合需求。未安裝 runtime 的環境可執行；允許正常暫存解壓，不要求零磁碟寫入。
- **驗證：** 記錄 OS build／架構、runtime 狀態、EXE hash、每項通過／失敗／未執行；必要時提供截圖及錯誤內容。GitHub runner 有預裝 runtime 或較新 OS 時，不當成此任務證據。

### T12 — 跨主機內網 SNMP 驗收

- **對應：** SNMP-01～04、UI-04；AC-09。
- **工作：** 使用者在 Windows 執行同一發行 EXE，綁定實際網卡 IPv4；從另一台內網主機查詢。AI 提供位址、port 與必要防火牆規則的操作說明，不自動改防火牆。
- **完成條件：** v1／v2c GET、walk、v2c bulkwalk 正常，設備值及 UI 收送狀態合理；停止後不再服務，重新開始可恢復。結果不只來自 localhost。
- **驗證：** 記錄兩端 OS、工具、網卡端點、命令與結果、EXE hash。網卡速度及網路設備不設門檻，此任務只驗證基本內網功能，不證明容量或 p99 目標。
